You are converting an animation-pipeline script into the ViStoryBench `story.json` format.

You will be given the animation script for a story named `{TARGET_NAME}`. It contains:
- `characters`: a list of characters, each with a numeric `id` and a visual `description`.
- `clips`: a list of shots, each with a numeric `id`, an `environment` (background/setting) and a
  `description` (the shot's visual composition, sometimes containing dialogue lines written as
  `Dialogue(Character[N]): '...'`).

Characters are referenced inside clip text as `Character[N]`, where `N` is the character `id`.

## Output format

Return a single JSON object shaped exactly like this:

```
{
  "Story_type": {"en": "<genre in English>", "ch": "<genre in Chinese>"},
  "Characters": {
    "<name>": {
      "source_id": <the character's id from the input>,
      "tag": "<realistic_human | unrealistic_human | non_human>",
      "name_en": "<same as the key>",
      "name_ch": "<Chinese label>",
      "prompt_en": "<appearance in English>",
      "prompt_ch": "<appearance in Chinese>",
      "num_of_appearances": <integer>
    }
  },
  "Shots": [
    {
      "index": <integer, exactly the clip id>,
      "Plot Correspondence":     {"en": "...", "ch": "..."},
      "Setting Description":     {"en": "...", "ch": "..."},
      "Shot Perspective Design": {"en": "...", "ch": "..."},
      "Characters Appearing":    {"en": ["<name>"], "ch": ["<Chinese label>"]},
      "Static Shot Description": {"en": "...", "ch": "..."}
    }
  ]
}
```

## Naming

Give each character a simple generic label based on their apparent type and appearance —
`boy1`, `girl1`, `man1`, `woman1`, `elf1`, `knight1`, `dog1`, `monster1`, and so on.
Number them from 1 within each type (`girl1`, `girl2`, ...).

- Lowercase ASCII letters and digits only. No spaces, punctuation, or accents — the label is used
  as a directory name.
- The key in `Characters` MUST be identical to `name_en`.
- `name_ch` is a short Chinese label for the same character, e.g. `boy1` -> `男孩1`,
  `elf1` -> `精靈1`.

## Rules

CHARACTERS
- `source_id` MUST be the character's `id` from the input. Keep characters in input `id` order.
- `tag`:
  - `realistic_human` — photorealistic human beings.
  - `unrealistic_human` — stylized / illustrated / anime / manga human beings, including elves and
    other humanoid fantasy races. Use this for typical anime or manga characters.
  - `non_human` — animals, creatures, robots, objects.
- `prompt_en` is the character's appearance, taken from the input `description`. Keep the concrete
  visual details (hair, eyes, build, clothing, accessories). Do not add plot.
- `num_of_appearances` is the number of shots the character appears in.

SHOTS
- Emit exactly one shot per clip, in ascending `id` order. `index` MUST equal the clip's `id` —
  never renumber, never start from 0.
- `Setting Description`: the environment/background, based on the clip's `environment`.
- `Static Shot Description`: what is visible in the frame — positions, poses, expressions, actions,
  composition. Base it on the clip's `description`, but REMOVE all dialogue lines (anything of the
  form `Dialogue(Character[N]): '...'`) and REMOVE the camera framing phrases you move into
  `Shot Perspective Design`. Replace every `Character[N]` reference with that character's label.
- `Shot Perspective Design`: camera framing and angle only, e.g. "Extreme close-up shot, profile
  view", "Eye-level medium shot", "Low-angle wide shot". If the clip states no framing, infer the
  most plausible one from the composition. Keep it short.
- `Plot Correspondence`: one or two sentences of narrative — what happens in this beat. Dialogue
  meaning belongs here: if the clip contains dialogue, fold its content into the narrative. Do not
  describe the camera here.
- `Characters Appearing`: characters actually VISIBLE in the frame — not those merely mentioned or
  speaking off-screen. `en` uses the labels exactly as keyed in `Characters`; `ch` lists the
  matching Chinese labels in the SAME ORDER. If no character is visible, use empty lists `[]`.

LANGUAGE
- Every text field needs both `en` and `ch` (Simplified Chinese). The Chinese must be a faithful
  translation of the English, not a summary.

OUTPUT
- Return raw JSON only. No markdown fences, no commentary, no trailing text.
